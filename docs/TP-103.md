# TP-103 — Supplier Import Service

## Beschreibung
Ein Application Service verarbeitet ERP-Lieferantenreferenzen in konfigurierbaren Batches. Ungültige Datensätze werden protokolliert; Infrastrukturfehler werden bewusst an den Aufrufer weitergegeben, damit ein zukünftiger Messenger-Consumer Retry und Dead-Letter-Handling übernehmen kann.

## Dateien
- Application/Import/SupplierImportRow.php: DTO
- Application/Import/SupplierImportRowFactory.php: Payload-Typvalidierung
- Application/Import/SupplierImportService.php: Batch-Upsert und strukturierte Logs
- Application/Import/SupplierImportResult.php: Ergebnis
- tests/Unit/SupplierImportRowFactoryTest.php

## Beispiel
```php
$result = $service->import([
    new SupplierImportRow('BOSCH', 'ERP-123'),
    new SupplierImportRow('SIEMENS', 'ERP-456'),
], $context, 100);
```

## Offene Punkte vor Produktivbetrieb
- Die deterministic UUID policy aus TP-102 und DAL-Versionierung prüfen.
- Ein Fehler nach mehreren erfolgreichen Batches führt zu Teilimporten. Wiederholbarkeit und Checkpoints müssen vor Messenger-Integration definiert werden.
- `accepted` zählt erfolgreich übergebene Zeilen, nicht eindeutig neue Datenbankdatensätze.
- Doppelte externe IDs innerhalb eines Batches und bereits vorhandene Daten müssen in Integrationstests geprüft werden.
- Kein echter ERP-Client, Scheduler, Queue-Consumer oder HTTP-Endpunkt in diesem Ticket.
- Laufende Shopware-Container- und Integrationstests stehen aus.
